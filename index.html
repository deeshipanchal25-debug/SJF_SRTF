01 · INTRODUCTION

What is the topic?

CPU scheduling is the operating-system activity of selecting a process from the ready queue to use the CPU. This project focuses on two shortest-job scheduling methods.

Shortest Job First (SJF)

Non-preemptive. When the CPU becomes free, it chooses the ready process with the smallest burst-time value. The selected process runs until it finishes.

Shortest Remaining Time First (SRTF)

Preemptive. It chooses the ready process with the least remaining execution time. A newly arrived process can interrupt the current process if its remaining time is shorter.

Research connection: The selected approach explores predicting CPU burst times with machine-learning methods so that SJF/SRTF can make scheduling decisions when the exact future burst time is not known.

02 · KEY FINDINGS FROM THE RESEARCH REVIEW

What the research approach highlights

1

Burst-time information matters

SJF and SRTF rely on burst-time knowledge or estimates. If the value is inaccurate, the scheduler may choose a less suitable process.

2

Prediction can inform scheduling

The reviewed approach considers ML models such as KNN, SVM, Decision Tree, Random Forest, XGBoost and ANN to estimate CPU burst time. An estimate can be supplied to SJF/SRTF as the selection value.

3

Compare scheduling outcomes

The effect of an estimate can be studied using the same process workload and metrics such as completion time, turnaround time, waiting time and the execution sequence.

4

Prediction has limitations

Prediction quality depends on the data and workload. Errors can change the scheduling order, and building a real ML model requires training, evaluation and integration.

Evidence note: These are research-review takeaways recorded in the project report, not verified numerical results from a reproduced experiment. This website does not claim that a machine-learning model has been trained.

03 · APPLICATION

How the research idea is applied

The simulator compares scheduling based on the actual burst times with scheduling based on user-supplied estimated burst times. The actual burst time controls how long each process really runs in this model; the estimate controls the scheduler's choice.

05 · INTERPRETATION

What to observe

  • Does the estimated burst-time order differ from the actual burst-time order?
  • Does the estimated schedule change average waiting time or turnaround time for this workload?
  • Does SRTF change its running process when a shorter remaining estimate arrives?
  • Are estimates close enough to the actual burst times to produce a similar schedule?

Important: A lower average time in one test does not prove that a prediction method is always better. Results depend on the chosen workload and the quality of the estimates. The estimates here are entered manually, not generated by an ML model.
